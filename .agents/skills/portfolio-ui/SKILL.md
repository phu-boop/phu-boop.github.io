# Portfolio UI/UX Design System

**Design System Specification & Engineering Rules**
**Target Identity:** Nguyễn Lê Anh Phú — Backend Software Engineer

---

## 1. DESIGN PHILOSOPHY

### Visual Personality

The design represents an **Architectural Engineering Terminal**. It communicates
high-throughput systems design, precision, reliability, and deep technical
competency. It mirrors modern developer tools (Datadog, Warp, Vercel
infrastructure consoles, Linear) without degenerating into a chaotic
multi-dashboard display.

### Emotional Tone

- **Grounded & Direct:** Direct typography and technical metrics. Zero fluff.
- **Architectural Precision:** Structural layouts with visible system pipelines,
  data pathways, and explicit relations between UI elements.
- **Controlled Power:** Deep near-black dark mode with high-contrast, razor-thin
  focal points in electric cyan and subtle purple.
- **High-End Precision:** Exceptional whitespace discipline, perfectly calculated
  scale transitions, and editorial layout balance.

### Design Principles

1. **Structure Over Decoration:** Every visual accent (lines, nodes, borders)
   must represent a structural boundary or a system data flow. Never add
   floating shapes, abstract geometric blobs, or ungrounded glows.
2. **Restrained Energy:** Electric cyan (`#00E5FF`) is a low-frequency,
   high-impact asset. It acts strictly as a signal light or key data anchor.
3. **Monospace as Meta-Data:** Sans-serif handles high-level human reading;
   monospace handles systemic truth (metrics, paths, statuses, code, stack tags).
4. **Asymmetric Dynamic Equilibrium:** Balance heavy editorial text blocks with
   dense technical system diagrams across asymmetric grid splits.

### Immutable Visual Decisions

- **Never use light mode.** The architecture requires a deep charcoal/near-black canvas.
- **Never use pure black (`#000000`) for card surfaces.** Use layers of off-black
  charcoal (`#0D1117`, `#161B22`) with low-opacity borders (`rgba(255,255,255,0.08)`).
- **Never use fully saturated neon fills.** Accents exist as fine lines, subtle
  text fills, indicator dots, or highly diffused back-glows.
- **Keep decorative elements subordinate to content.** Architecture graphics must
  recede into low-contrast tones (`#30363D`).

## 2. ANTI-AI DESIGN RULES

To guarantee the website looks designed by a senior human product designer, not
generated by a standard AI/Tailwind template, strictly enforce these anti-patterns:

| WHAT TO AVOID | WHY IT LOOKS GENERIC | WHAT TO DO INSTEAD |
|---|---|---|
| Floating Purple/Blue Blobs & Unconnected Glow Blur | Unfocused ambient background glows scream "AI template" | Structural grid lines with precise radial masks behind system node points only |
| Uniform 3-Column Card Grids across every section | Repetitive card grids are default outputs for AI and page builders | Asymmetrical grid layouts (e.g., 60/40 splits, full-width feature cards, terminal sidebars) |
| Oversaturated Glowing Gradient Card Backgrounds | Heavy gradient fills destroy contrast, look like a gaming/crypto platform | Solid dark surfaces with 1px precision borders and subtle hover edge highlights |
| Generic Rounded Pill Tags with bright background fills | Standard rounded-full colorful tags create visual clutter and look cheap | Square or low-radius (4px) tags with neutral border, dark bg, and monospace text |
| Meaningless AI / Web3 Visual Graphics | 3D floating shapes or shiny spheres convey zero technical authority | Functional backend diagrams: API -> Queue -> DB architecture |
| Generic "Buzzword" Copy | "Passionate developer building next-gen seamless experiences" sounds fake | Technical context: "Distributed queues, ACID consistency, high-throughput microservices" |
| Heavy Glassmorphism (`backdrop-blur-xl`) with white translucent borders | Massive blur overlays look messy and slow down render performance | Subtle solid overlays (`rgba(13, 17, 23, 0.85)`) with sharp, fine borders |

## 11. MOTION & INTERACTION

### Transition Durations & Easings

| Type | Duration | Easing |
|---|---|---|
| Standard interface transition | `150ms – 200ms` | `cubic-bezier(0.16, 1, 0.3, 1)` |
| Card hover elevation | `250ms` | `cubic-bezier(0.16, 1, 0.3, 1)` |
| Accordion / layout expand | `350ms` | `cubic-bezier(0.87, 0, 0.13, 1)` |

### Animation Rules

- **Scroll Reveal:** `16px` vertical offset, `400ms` duration, stagger children by `50ms`.
  No extreme scale flips or rotational animations.
- **Data Stream:** `stroke-dashoffset` keyframe on SVG paths over `3s–5s` infinite.
  Smooth and subtle — never distracting.
- **NO:** Bouncing particles, floating cursor effects, heavy particle systems.

### Reduced Motion

```css
@media (prefers-reduced-motion: reduce) {
  *, ::before, ::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
```

## 17. ANTIGRAVITY ENFORCEMENT DIRECTIVES

These directives are **non-negotiable** for any AI agent coding this portfolio:

1. **TOKEN COMPLIANCE** — Declare all values as CSS custom properties in `:root`.
   Use `var(--token-name)` everywhere. No raw hex in component CSS.

2. **COLOR RESTRICTION** — No new accent colors outside cyan (`#00E5FF`) and
   purple (`#7928CA`). Cyan surface area MUST NOT exceed 2% of viewport.

3. **GRID CONSTRAINTS** — Section 1 (Hero): 58/42 split. Section 2 (Philosophy):
   33/67 split. Featured Projects: alternating full-width cards + 2-col detail grid.
   Never identical 3-col card grids across all sections.

4. **GRAPHICAL ELEMENTS** — No abstract floating shapes, glowing background balls,
   or generic stock illustrations. All diagrams MUST represent actual system
   engineering workflows from the real projects. Node lines MUST be SVG paths
